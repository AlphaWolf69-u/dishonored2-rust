# Flash UI (Iggy) runtime

The game's UI is RAD Iggy: AS3 movies in `.iggy` files with BC7 textures in
`.raw.iggytex`. The rewrite runs the installed movies in its own player.
Research notes live in `artifacts/ui-pause/notes-*.md` (local only).

## Evidence rules

- Native class shapes (members, namespaces, constants, trivial handlers) come
  only from the generated table. A native Iggy implements without a Rust port
  is `MethodKind::Unimplemented` and fails with its address; the test
  `rust_natives_match_iggy_table` rejects Rust members Iggy does not declare.
- Startup and tick order follow `FUN_141028160` and `FUN_141021b40`
  (allocate-then-construct timeline children, post-order constructors,
  deferred gotos with modify placements applied at once, broadcasts in
  reverse registration order).
- The text language follows `arkLangSystem`; every installed language loads
  both pause movies (`pause_movies_load_in_every_installed_language`).

## Open questions and blockers

1. Error subclass construction: Error has a native constructor (0x14107ef30)
   but TypeError and the other subclasses register the IllegalOperationError
   stub. Whether `new TypeError()` reaches the stub is unresolved; the rewrite
   keeps Error's constructor. Next: trace the generic path of `FUN_141044820`
   past the type-tag switch, or break on 0x1410b38e0 in the running game.
2. `m_isLightVM` default: classes gated on `VM+0x6b40` are installed on the
   assumption that the pause decl's unset bit is 0. Next: read the decl
   default in `FUN_1404f2cd0` or the VM flag at runtime.
3. Rendering not yet ported: filters other than the text emulation of
   `FUN_14102e950` (drop shadows: one offset copy for blurs up to 2, else
   three rings of copies; bevels and script filters such as the message
   box blur and colour matrix are not ported), blend modes beyond normal/add,
   cacheAsBitmap, the glyph bitmap cache, the exact curve flattening tolerance
   (`player+0x1e80`), game textures (save screenshots). Masks and clip layers
   follow `FUN_141037100` and GDraw's stencil state (notes-masks.md) except
   the mask scissor (no pixel effect), the off-Stage mask prefix (`P+0x2788`)
   and masks under 3D.
4. Game state the rewrite does not simulate yet, so the pause state writes
   what the game would for "unavailable": no save writer or loader (save,
   load and quick entries locked), no mission component (the chapter header
   takes the branch for no current mission: the loaded map's mapinfo
   `m_loadingInfo`; restart lock), no tutorial log, no statistics component,
   no mission+ flag, no player character (`DH2_DEBUG_CHARACTER=emily`
   selects Emily's movie). Callbacks needing them (`CreateSave`,
   `LoadSave`, `QuickLoad`, `QuickSave`, `Restart`, `BackToMain`,
   `OnTutorialRead`, `DevGUI`) are logged as unhandled.
5. Options, remaining gaps (notes-options.md, notes-visuals-runtime.md):
   - Visuals AUTO quality needs the CPU/GPU scoring (`FUN_14050b410`,
     `FUN_14050b760`, the known-GPU table); AUTO rows are not applied.
   - The renderer does not observe cvars live: changed visual, audio and
     control cvars reach the rewrite through `dishonored2Config.cfg` on the
     next start. The display mode switch (`renderer +0x200`), the
     keep-changes box and its timeout answer, exclusive-fullscreen refresh
     (`FUN_14036aa40`) and the texture streamer calls are not ported.
   - The adapter list (+0x1a0) needs the D3D11 init acceptance test; it is
     empty (VIDEOCARD is main-menu only).
   - The gamma FX entity and the pause FX toggle around the gamma screen.
   - SetDifficulty's entity attribute reset/apply (`FUN_1406491f0`,
     `FUN_14060b970`) and its profile dictionary writes (`FUN_1406492c0`,
     needs a profile.bin writer).
   - The control-scheme `image` (the image manager's name for
     `m_layoutImage`, `FUN_1400607f0` field +8) is not written.
   - Audio: subtitle level and language re-application after Apply.
   - AUDIO_LANGUAGE's language-list check (`FUN_140504ee0`) for the main menu.
   - Whether repeated callback registration duplicates handlers
     (`FUN_14002cd20`).
6. Message boxes (`gameplay/message_box.rs`, `global.iggy` over the pause
   movie with the focus stack) are hosted. Not ported: the box's playback
   requests beyond show/hide, the NOTIFICATION game-logic state (the pause
   state already pauses), `g_skipMessageBox`, installation/demo boxes,
   accept-all-controller-inputs (`FUN_1400326a0`), and passing an AS3 data
   object between movies (the global call gets 0). `BackToMain` needs the
   main-menu state.
7. Pause screen FX (`app/pause_fx.rs`): `m_screenFX` (`pause.fx`, the
   `env/fx/ui_pause` override: pause colour cube and depth of field) starts
   on OnEnter or `EnableUIPostFX`, advances by clock group 0's delta (kept
   from the last game frame while the paused frame skips the clock step,
   `FUN_1407913f0`), and is removed on OnExit or `DisableUIPostFX`; its
   blend weights the override in 88e220's override stage (numeric values
   base + (v - base)·w, the cube into `m_overrideColorCubes`). Open: the FX
   render entity's time scale (`+0xf8`) is taken as 1.0 (its initializer is
   not traced); `r_skipDOF` has no consumer in the renderer.
8. Sound: `PostSoundEvent` and UI sound IDs (`_soundHandler.soundsList`)
   are not connected to audio.
9. Tab focus traversal on keyDown (`FUN_141027340`) and SimpleButton states
   (`FUN_1410279b0`) are not ported.
10. PerspectiveProjection follows the natives (own or linked values,
    focalLength from the stage width); the root timeline's projection is the
    one rendering uses (`P+0x2510` is the root, `P+0x26b0` the Stage).
11. `profile.bin` layout (pair count at 0x1a) is read from the file, not
    from a traced loader.

## Pause menu timing

The movie runs on its own thread; each frame sends its input and tick and
waits for that tick's draw list (the game ticks Iggy within the frame).
Queued input is merged so it never waits behind a backlog of frames. The
catalog, decoded bitmaps, movie bytes and string tables are kept between
opens, and while the menu is closed the next player is built ahead
(movie, libraries, screen size, bitmaps); an open then only reads the current
state (options, saves) and shows the menu. Every open uses a new player. `DH2_DEBUG_PAUSE_TIMING=1` logs
the open phases and, each second, the queue wait and the per-frame work
(input, tick, options, draw list).
